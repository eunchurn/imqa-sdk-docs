## Web Agent 설치 및 사용

IMQA 성능 모니터링 서비스에서 웹 성능 모니터링을 사용하기 위해서는 [설치 방법](./installation.mdx)을 참조하여 `@imqa/web-agent`를 설치하여 자동 계측 방법으로 사용하거나 아래에 설명된 속성 필드와 스키마를 참조하여 사용자가 직접 성능 데이터를 수집하여 컬렉터로 HTTP혹은 gRPC로 전송하여 사용할 수 있습니다.

## 속성 필드 설명

### 리소스 속성

가장 최상의 리소스 속성으로 앱과 에이전트의 메타 데이터를 가지고 있습니다.

- `service.name`: 서비스 이름
- `service.version`: 서비스 버전
- `telemetry.sdk.language`: 프로그래밍 언어 (webjs)
- `telemetry.sdk.name`: SDK 이름 (opentelemetry)
- `telemetry.sdk.version`: SDK 버전
- `process.runtime.name`: 런타임 이름 (browser)
- `os.name`: 운영체제 이름
- `os.version`: 운영체제 버전
- `imqa.browser.device`: 디바이스 타입
- `imqa.browser.name`: 브라우저 이름
- `imqa.browser.version`: 브라우저 전체 버전
- `imqa.browser.version_major`: 브라우저 메이저 버전
- `service.key`: 서비스 키
- `imqa.agent.version`: IMQA 에이전트 버전
- `imqa.rum.version`: RUM 에이전트 버전 (`@imqa/web-agent` 의 버전이 자동으로 추가됩니다)
- `rum.scriptInstance`: RUM 스크립트 인스턴스 식별자
- `application`: 애플리케이션 이름 (설정된 경우)
- `environment`: 환경 이름
- `deployment.environment`: 배포 환경 (production, staging 등)
- `sampling.probability`: 샘플링 확률 (0 ~ 1 사이의 값)
- `imqa.telemetry.sdk.export_timestamp`: 데이터 내보내기 타임스탬프
- `host.ip`: IP 주소
- `host.ip.geolocation`: IP 주소의 지리적 위치 정보 (콜렉터에서 추가)
- `device.model.name`: 디바이스 모델 이름
- `user_agent.original`: User Agent 문자열
- `session.id`: 사용자 세션 ID (중요: 세션 그룹화를 위해 필수)
- `network.carrier.name`: 통신사 이름
- `network.connection.subtype`: 네트워크 연결 유형
- `device.battery.status`: 배터리 상태
- `device.cpu.util`: CPU 사용률
- `device.memory.util`: 메모리 사용률

### 스팬 속성

#### 기본 스팬 속성

모든 스팬에 공통적으로 포함되는 속성들입니다.

- `location.href`: 현재 페이지의 URL
- `environment`: 환경 이름 (development, production 등)
- `deployment.environment`: 배포 환경
- `screen.name`: 화면/페이지 이름
- `screen.type`: 화면 타입 (e.g., "page", "route", "modal", "dialog")
- `session.id`: 세션 ID
- `url.full`: 전체 URL
- `document.visibilityState`: 문서의 가시성 상태 ("visible" 또는 "hidden")
- `component`: 컴포넌트 식별자 (계측 유형에 따라 다름)
- `span.type`: 스팬 타입 (e.g., "render", "xhr", "fetch", "user-interaction", "connectivity")
- `action.type`: 스팬의 액션 타입 ("document_loads", "xhr_requests", 또는 "route_changes")

#### Document Load 스팬 속성

Document Load 스팬은 페이지 로딩 과정을 캡처하며 다음 속성을 포함합니다:

- `http.url`: 문서 URL
- `http.response_content_length`: 응답 콘텐츠 길이 (바이트)
- `http.response_content_length_uncompressed`: 압축 해제된 응답 콘텐츠 길이 (바이트)
- `http.request.method`: HTTP 메서드 (일반적으로 "GET")
- `http.user_agent`: 브라우저 유저 에이전트
- `document.referrer`: 이전 페이지 URL (해당되는 경우)
- `screen.xy`: 화면 해상도 (예: "1920x1080")

#### XHR/Fetch 스팬 속성

XHR 및 Fetch 스팬은 HTTP 요청을 캡처하며 다음 속성을 포함합니다:

- `http.method`: HTTP 메소드 (GET, POST 등)
- `http.url`: 요청 URL
- `http.status_code`: HTTP 상태 코드
- `http.status_text`: HTTP 상태 텍스트
- `http.host`: 호스트 이름
- `http.scheme`: URL 스키마 (http, https)
- `http.user_agent`: User Agent 문자열
- `http.response_content_length`: 응답 콘텐츠 길이 (바이트)
- `root_span.operation`: 루트 스팬의 이름
- `root_span.http.url`: 루트 스팬의 URL

고급 모드(`advancedNetworkCapture`)를 활성화 한 경우에 다음 속성도 포함될 수 있습니다:

- `http.request.header.*`: 요청 헤더 정보
- `http.request.body`: 요청 본문 (POST, PUT 등)
- `http.response.header.*`: 응답 헤더 정보
- `http.response.body`: 응답 본문

#### 사용자 상호작용 스팬 속성

사용자 상호작용 스팬은 클릭 등의 이벤트를 캡처하며 다음 속성을 포함합니다:

- `event_type`: 이벤트 타입 (click, dblclick 등)
- `target_element`: 대상 요소 유형
- `target_xpath`: 대상 요소의 XPath
- `target.id`: 대상 요소 ID (있는 경우)
- `target.classList`: 대상 요소의 클래스 목록

#### Long Task 스팬 속성

Long Task 스팬은 성능에 영향을 주는 긴 작업을 캡처하며 다음 속성을 포함합니다:

- `longtask.name`: Long task의 유형 (e.g., "self")
- `longtask.entry_type`: 항목 유형 (일반적으로 "longtask")
- `longtask.duration`: Long task의 지속 시간 (ms)
- `longtask.startTime`: Long task의 시작 시간
- `longtask.attribution.name`: 어트리뷰션 소스 이름
- `longtask.attribution.entry_type`: 어트리뷰션 항목 유형
- `longtask.attribution.start_time`: 어트리뷰션 시작 시간
- `longtask.attribution.duration`: 어트리뷰션 지속 시간
- `longtask.attribution.container_type`: 컨테이너 유형 (e.g., "window")
- `longtask.attribution.container_src`: 컨테이너 소스
- `longtask.attribution.container_id`: 컨테이너 ID
- `longtask.attribution.container_name`: 컨테이너 이름
- `root_span.operation`: 루트 스팬의 이름
- `root_span.http.url`: 루트 스팬의 URL
- `http.action_type`: 트레이스의 HTTP 액션 타입

#### 라우트 변경 스팬 속성

라우트 변경 스팬은 SPA에서의 페이지 전환을 캡처하며 다음 속성을 포함합니다:

- `prev.href`: 이전 페이지 URL
- `component`: 일반적으로 "route"로 설정
- `span.type`: "user-interaction"으로 설정

#### WebSocket 스팬 속성

WebSocket 통신을 캡처하며 다음 속성을 포함합니다:

- `net.sock.peer.addr`: WebSocket 서버 주소
- `net.sock.peer.port`: WebSocket 서버 포트
- `websocket.operation`: 작업 유형 ("connect", "message", "close")
- `websocket.url`: WebSocket URL (연결 스팬의 경우)
- `websocket.protocol`: 사용된 WebSocket 프로토콜
- `websocket.message.type`: 메시지 유형 ("text", "binary" 등)
- `websocket.message.size`: 메시지 크기 (바이트)
- `websocket.close.code`: WebSocket 종료 코드
- `websocket.close.reason`: 연결 종료 이유

#### Core Web Vitals 스팬 속성

웹 바이탈 메트릭을 캡처하며 다음 속성을 포함합니다:

- `web-vital.name`: 웹 바이탈 메트릭 이름 (e.g., "ttfb", "fcp", "lcp", "cls", "fid", "inp")
- `web-vital.value`: 웹 바이탈 메트릭 값
- `web-vital.delta`: 웹 바이탈 메트릭 델타 값
- `web-vital.navigation_type`: 네비게이션 유형 (e.g., "reload")
- `web-vital.rating`: 성능 등급 (e.g., "good", "needs-improvement", "poor")

추가로 각 스팬은 다음 메트릭 중 하나를 포함합니다:
- `fid`: First Input Delay (밀리초)
- `lcp`: Largest Contentful Paint (밀리초)
- `cls`: Cumulative Layout Shift 점수
- `ttfb`: Time to First Byte (밀리초)
- `fcp`: First Contentful Paint (밀리초)
- `inp`: Interaction to Next Paint (밀리초)

#### 연결 상태 스팬 속성

네트워크 연결 상태를 캡처하며 다음 속성을 포함합니다:

- `online`: 네트워크 연결 상태 (true = 온라인, false = 오프라인)
- `span.type`: "connectivity"로 설정

#### 가시성 상태 스팬 속성

페이지 가시성 상태 변경을 캡처하며 다음 속성을 포함합니다:

- `hidden`: 페이지 숨김 상태 (true = 숨김, false = 표시)
- `span.type`: "visibility"로 설정

### 이벤트 속성

스팬은 중요한 이벤트를 포함할 수 있으며, 이벤트 타입에 따라 다양한 속성을 포함합니다:

#### Document Load 이벤트

- `fetchStart`: 페치 프로세스 시작
- `unloadEventStart`: 이전 페이지 언로드 이벤트 시작
- `unloadEventEnd`: 이전 페이지 언로드 이벤트 종료
- `domInteractive`: DOM이 상호작용 가능한 상태
- `domContentLoadedEventStart`: DOMContentLoaded 이벤트 시작
- `domContentLoadedEventEnd`: DOMContentLoaded 이벤트 종료
- `domComplete`: DOM 구성 완료
- `loadEventStart`: load 이벤트 시작
- `loadEventEnd`: load 이벤트 종료
- `firstPaint`: 첫 번째 페인트
- `firstContentfulPaint`: 첫 번째 콘텐츠풀 페인트

#### XHR/Fetch 이벤트

- `fetchStart`: 리소스 페치 시작
- `domainLookupStart`: DNS 조회 시작
- `domainLookupEnd`: DNS 조회 종료
- `connectStart`: 서버 연결 시작
- `secureConnectionStart`: 보안 연결 핸드셰이크 시작
- `connectEnd`: 서버 연결 완료
- `requestStart`: 요청 시작
- `responseStart`: 응답 첫 바이트 수신
- `responseEnd`: 응답 마지막 바이트 수신
- `open`: XHR 객체 초기화 (XHR만 해당)
- `send`: 요청 전송 (XHR만 해당)
- `loaded`: 요청 완료 (XHR만 해당)
- `error`: 오류 발생 (해당되는 경우)

#### 사용자 상호작용(user-interaction) 이벤트

`@opentelemetry/instrumentation-user-interaction`에 의해 수집되는 이벤트:

- `click`: 사용자가 요소를 클릭할 때 발생
- `dblclick`: 사용자가 요소를 더블 클릭할 때 발생
- `submit`: 폼이 제출될 때 발생
- `reset`: 폼이 리셋될 때 발생
- `pause`, `play`: 미디어 요소(비디오, 오디오)의 재생 상태가 변경될 때 발생
- `dragstart`, `dragend`: 드래그 동작이 시작되거나 끝날 때 발생
- `drop`: 드래그된 요소가 드롭될 때 발생

#### 페이지 가시성 이벤트

- `pageshow`: 페이지가 표시될 때 발생하는 이벤트
- `pagehide`: 페이지가 숨겨질 때 발생하는 이벤트

### 로그 속성

오류 및 예외에 대한 로그 데이터는 다음 속성을 포함합니다:

- `level`: 로그 레벨 (e.g., "info", "error", "warn", "debug")
- `message`: 실제 로그 메시지 내용
- `type`: 로그 타입 ("uncaughtException", "unhandledRejection", "consoleError", "documentError", "customError")
- `http.url`: 오류 발생 시 페이지 URL
- `root_span.operation`: 관련된 루트 스팬의 이름
- `root_span.http.url`: 관련된 루트 스팬의 URL
- `http.action_type`: 관련된 HTTP 액션 타입
- `element.xpath`: 오류가 발생한 DOM 요소의 XPath (해당하는 경우)
- `error`: 오류 플래그 (boolean)
- `error.name`: 오류 이름
- `error.message`: 오류 메시지
- `error.stack`: 스택 트레이스
- `exception.type`: 예외 유형
- `exception.message`: 예외 메시지
- `exception.stack`: 예외 스택 트레이스
- `exception.parsed_stacktrace`: 파싱된 스택 트레이스의 JSON 표현
- `arguments`: 콘솔 오류의 인자 (해당하는 경우)

### 성능 지표 데이터

`@imqa/web-agent`는 다양한 웹 애플리케이션 성능 지표를 자동으로 수집합니다. 주요 자동 계측 항목은 다음과 같습니다:

#### Document Load 성능 지표

웹 페이지 로딩 프로세스에 대한 성능 정보를 수집합니다:

- 페이지 로드 시간
- DOM 처리 시간
- 리소스 로딩 시간

#### API 요청 성능 지표

XHR 및 Fetch 요청에 대한 성능 정보를 수집합니다:

- 요청 지연 시간
- 응답 크기
- 성공/실패 상태
- 도메인 조회 시간
- 연결 설정 시간

#### 웹 바이탈 지표

사용자 경험을 측정하는 핵심 웹 바이탈 지표를 수집합니다:

##### LCP (Largest Contentful Paint)
페이지가 로드를 시작한 시점부터 가장 큰 텍스트 블록이나 이미지 요소가 화면에 렌더링될 때까지의 시간을 측정합니다. 이 지표는 인지된 로딩 성능에 중요합니다.

- **좋음**: < 2.5초
- **개선 필요**: 2.5초 - 4초
- **나쁨**: > 4초

##### FID (First Input Delay)
사용자가 페이지와 처음 상호작용(클릭, 탭, 키 입력)한 시점부터 브라우저가 해당 상호작용에 대응하여 이벤트 핸들러 처리를 시작할 수 있는 시간까지를 측정합니다. 이 지표는 상호작용성을 측정하는 데 중요합니다.

- **좋음**: < 100ms
- **개선 필요**: 100ms - 300ms
- **나쁨**: > 300ms

##### INP (Interaction to Next Paint)
FID의 대체 지표로, 사용자 방문 전체 수명 동안 발생하는 모든 클릭, 탭, 키보드 상호작용을 관찰하여 페이지의 전반적인 응답성을 측정합니다. 모든 상호작용에서 관찰된 시각적 피드백 지연 중 가장 나쁜 경우를 보고합니다.

- **좋음**: < 200ms
- **개선 필요**: 200ms - 500ms
- **나쁨**: > 500ms

##### CLS (Cumulative Layout Shift)
페이지 전체 수명 동안 발생하는 모든 예상치 못한 레이아웃 이동에 대한 개별 레이아웃 이동 점수의 합계를 측정합니다. 이 지표는 사용자가 예상치 못한 레이아웃 이동을 경험하는 빈도를 정량화하는 데 도움이 됩니다.

- **좋음**: < 0.1
- **개선 필요**: 0.1 - 0.25
- **나쁨**: > 0.25

##### FCP (First Contentful Paint)
페이지 로드 시작부터 페이지 콘텐츠의 일부가 화면에 렌더링될 때까지의 시간을 측정합니다. 이것은 사용자가 페이지가 로드되고 있음을 확인할 수 있는 첫 순간입니다.

- **좋음**: < 1.8초
- **개선 필요**: 1.8초 - 3초
- **나쁨**: > 3초

##### TTFB (Time To First Byte)
사용자가 탐색을 시작한 시점부터 응답의 첫 바이트가 도착하기 시작할 때까지의 시간을 측정합니다. TTFB는 모든 로딩 측정 항목에 영향을 미치는 기본 지표입니다.

- **좋음**: < 800ms
- **개선 필요**: 800ms - 1800ms
- **나쁨**: > 1800ms

#### 사용자 상호작용 지표

사용자 상호작용에 대한 응답성 정보를 수집합니다:

- 클릭 이벤트 응답 시간
- 폼 제출 성능
- 사용자 인터페이스 응답성

#### 네트워크 연결 지표

네트워크 연결 상태 변화에 대한 정보를 수집합니다:
- 오프라인/온라인 상태 전환
- 연결 불안정 이벤트

#### 오류 및 예외 추적

애플리케이션 오류 및 예외에 대한 정보를 수집합니다:
- 캐치되지 않은 예외
- 처리되지 않은 프라미스 거부
- 콘솔 오류 및 경고
- 커스텀 오류

## IMQA Schema

IMQA Agent는 OpenTelemetry 스키마 구조를 따르며 다른 어떤 Opentelemetry 계측과 호환성을 제공합니다. 이 스키마는 트레이스, 로그, 메트릭을 포함한 원격 측정 데이터의 수집과 표현을 표준화합니다. 스키마의 구조는 최상의 resource를 기반으로 scopeTraces, scopeLogs, scopeMetrics 를 페이로드로 IMQA 컬렉터(Collector)에 전달합니다.

### 리소스

`resource` 객체는 원격 측정 데이터를 생성하는 메타데이터 Entity를 나타냅니다. 이는 모든 트레이스, 로그, 메트릭에 공통적으로 사용됩니다.

```json
{
  "resource": {
    "attributes": [
      {
        "key": "service.name",
        "value": {
          "stringValue": "example-service"
        }
      },
      {
        "key": "telemetry.sdk.language",
        "value": {
          "stringValue": "webjs"
        }
      },
      {
        "key": "telemetry.sdk.name",
        "value": {
          "stringValue": "opentelemetry"
        }
      },
      {
        "key": "telemetry.sdk.version",
        "value": {
          "stringValue": "1.25.1"
        }
      },
      {
        "key": "imqa.rum.version",
        "value": {
          "stringValue": "0.0.1"
        }
      },
      {
        "key": "sampling.probability",
        "value": {
          "intValue": 1
        }
      },
      {
        "key": "imqa.telemetry.sdk.export_timestamp",
        "value": {
          "doubleValue": 1725951502887.2
        }
      }
    ],
    "droppedAttributesCount": 0
  }
}
```

### 트레이스
트레이스는 분산 시스템을 통한 요청의 흐름을 나타냅니다. 이는 트레이스 내의 개별 작업을 설명하는 스팬으로 구성됩니다.

> [!TIP]
> scope 에는 스팬 계측에 대한 메타정보, spans 은 여러 스팬이 담겨있습니다. 개별 스팬에는 `traceId` , `spanId` , `parentSpanId` 등이 담겨 있습니다. 커스텀 `attributes` 에는 메타데이터들이 담겨있습니다.(아래 예시 참조). 특별히 `attributes` 에는 `session.id` 이 담겨있습니다.

```json
{
  "resource": { /* ... 리소스 객체 ... */ },
  "scopeSpans": [
    {
      "scope": {
        "name": "@opentelemetry/instrumentation-document-load",
        "version": "0.39.0"
      },
      "spans": [
        {
          "traceId": "5b519960b8bf2d8a6cfad88005e96806",
          "spanId": "3e18a1b40aeecb1d",
          "parentSpanId": "5c3775573bc2064f",
          "name": "documentFetch",
          "kind": 1,
          "startTimeUnixNano": "1725951497919999902",
          "endTimeUnixNano": "1725951498195199902",
          "attributes": [
            {
              "key": "document.visibilityState",
              "value": {
                "stringValue": "visible"
              }
            },
            {
              "key": "session.id",
              "value": {
                "stringValue": "fa9a23bd3c432ca0aa945e4bc83904dc"
              }
            },
            {
              "key": "location.href",
              "value": {
                "stringValue": "http://localhost:3002/"
              }
            },
            {
              "key": "http.url",
              "value": {
                "stringValue": "http://localhost:3002/"
              }
            },
            {
              "key": "http.response_content_length",
              "value": {
                "intValue": 19723
              }
            },
            {
              "key": "http.response_content_length_uncompressed",
              "value": {
                "intValue": 67009
              }
            }
          ],
          "droppedAttributesCount": 0,
          "events": [
            /* XHR 이벤트 또는 렌더 이벤트는 아래에서 자세히 설명 */
          ],
          "droppedEventsCount": 0,
          "status": {
            "code": 0
          },
          "links": [],
          "droppedLinksCount": 0
        }
      ]
    }
  ]
}
```

### 메트릭 (미사용)

메트릭도 유사한 구조를 따를 수 있으며, 특정 메트릭 유형을 포함하도록 조정됩니다. 하지만 IMQA에서는 별도의 Metric은 수집하지 않으며, 스팬 데이터를 가지고 메트릭을 생성합니다.

```json
{
  "resource": { /* ... 리소스 객체 ... */ },
  "scopeMetrics": [
    {
      "scope": {
        "name": "metric-instrumention-name",
        "version": "metric-instrumentation-version"
      },
      "metrics": [
        {
          "name": "http.server.duration",
          "description": "HTTP 서버 요청의 지속 시간",
          "unit": "ms",
          "histogram": {
            "dataPoints": [
              {
                "startTimeUnixNano": "1725951497919999902",
                "timeUnixNano": "1725951498195199902",
                "count": 100,
                "sum": 1000.0,
                "bucketCounts": [50, 25, 15, 10],
                "explicitBounds": [0, 5, 10, 25],
                "attributes": [
                  /* ... 스팬과 유사한 속성들 ... */
                ],
                "droppedAttributesCount": 0
              }
            ],
            "aggregationTemporality": 2
          }
        }
      ]
    }
  ]
}
```

이 스키마는 트레이스, 로그, 메트릭 전반에 걸쳐 원격 측정 데이터를 수집하고 구성하기 위한 포괄적인 구조를 제공합니다. 이를 통해 분산 시스템에서 상세한 성능 모니터링과 문제 해결이 가능해지며, 특히 트레이싱 데이터의 XHR 및 렌더 이벤트를 통해 웹 애플리케이션 성능에 중점을 둡니다.
