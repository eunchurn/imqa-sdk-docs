## IMQA 4단계로 시작하기

1. **제공된 IMQA 관리자 계정** 또는 **통합 관리 역할(`SUPER_USER`) 계정의 로그인 ID**와 **비밀번호**를 입력 후 [로그인] 합니다.

<Gha keyword="TIP" title="IMQA 사용자 로그인">
IMQA는 기본 로그인 ID로 '이메일 주소'를 사용하고, 새로운 IMQA 사용자를 추가하고 관리할 수 있는 **사용자 관리** 기능을 제공합니다. 또한 기업 도입 환경에 따라 **인사정보 및 SSO 연동** 하여 로그인 방식이 다를 수 있습니다. 자세한 내용은 IMQA 담당자에게 문의하세요.
</Gha>

![admin guide 01](img/admin-guide-01.png)

2. **'관리 > 서비스 관리' 메뉴에서 IMQA에서 분석할 주요 업무 단위 서비스를 추가합니다.** 서비스로 여러 앱을 그룹화하여 모니터링 & 분석할 수 있습니다.

<Gha keyword="TIP" title="서비스 이름">
**IMQA는 SDK, 웹 브라우저에서 수집한 데이터를 식별하기 위해 서비스 이름을 사용합니다. **SDK, WebAgent 설치시 `ServiceNameSpace`로 사용할 이름**으로 등록해 주세요. 서비스 이름은 고유해야 하며, 다른 서비스 이름과 동일하게 설정하실 수 없습니다.
</Gha>

<Gha keyword="TIP" title="서비스 대표 이미지">
IMQA에서는 브랜드의 로고나 앱 서비스 아이콘 등의 이미지로 서비스 대표 이미지를 설정할 수 있습니다. 설정하지 않았을 경우 기본 IMQA 이미지로 표시됩니다. 
</Gha>

![admin guide 03](img/admin-guide-03.png)


3. **'관리 > 앱 관리' 메뉴에서 IMQA에서 분석할 새로운 앱을 등록하고 발급된 `앱 키`를 확인합니다.**

![admin guide 02](img/admin-guide-02.png)

- **IMQA SDK 설치 시, `서비스 이름` 과 Android / iOS 앱으로 생성한 `앱 키`를 사용하여 설치합니다.**
<Gha keyword="NOTE" title="IMQA Mobile SDK 설치">
IMQA의 Android SDK, iOS SDK, WebAgent는 각각 환경의 특성에 맞는 데이터를 수집합니다. Android / iOS 앱 등록 후 발급된 `앱 키`를 사용하여 SDK를 설치하세요.
</Gha>
- **IMQA WebAgent 설치 시, IMQA Mobile SDK와 연동 또는 웹 브라우저 환경을 계측하는 경우에 따라 `서비스 이름` 과 Web 앱으로 생성한 `패키지 이름`, `앱 버전`, `앱 키`를 사용하여 설치합니다.**
<Gha keyword="NOTE" title="IMQA WebAgent로 Mobile SDK와 연동 또는 웹 브라우저 환경을 계측하는 경우">
IMQA Mobile SDK와 연동시, 웹 브라우저 환경 계측에 따라 네이티브 SDK에서 전달한 정보를 자동으로 연계하거나, 별도 설정이 필요합니다. 자세한 내용은 **IMQA WebAgent 설치 가이드 > 옵션 상세 설명** 섹션을 참고해주세요.
</Gha>

4. **설치 후 통합 대시보드 또는 서비스 목록에서 데이터가 정상적으로 수집되는 것을 확인하실 수 있습니다!**

![admin guide dash-dev](img/admin-guide-dash-dev.png)

  <li>- **서비스 관리**: `SUPER_USER` 역할 사용자에게만 표시, 접근할 수 있습니다. **서비스 관리**와 **앱 관리**, **매핑 파일 관리**를 할 수 있습니다.</li>
  <li>- **감사 로그**: `SUPER_USER` 역할 사용자에게만 표시, 접근할 수 있습니다.</li>
</ul>
</Gha>
<Gha keyword="TIP" title="특정 서비스별 설정 기능 제공">
<p>'서비스 관리 > 앱 관리 & 매핑 파일 관리' 기능은 **특정 서비스별 설정 기능으로도 제공** 됩니다. 앱 접근 권한이 있고, MANAGER 이상의 권한이 있는 담당자가 직접 관리할 수 있습니다.</p>
<ul>
  <li>- **(특정 서비스의) 서비스 설정**: `MANAGER` 이상 역할 사용자에게만 표시, 접근할 수 있습니다. 해당 서비스에 속한 **앱 관리**, **매핑 파일 관리**를 할 수 있습니다.</li>
</ul>
</Gha>

## 1. 사용자 관리

IMQA 사용자 관리를 통해 IMQA 사용자를 조회하고 관리할 수 있습니다. 사용자별 권한을 소속 팀과 역할에 따라 기본 설정할 수 있습니다.

<Gha keyword="TIP" title="기업 인사정보 & SSO 연동">
IMQA는 기본 로그인 ID로 '이메일 주소'를 사용하고, 새로운 IMQA 사용자를 추가하고 관리할 수 있는 **사용자 관리** 기능을 제공합니다. 또한 기업 도입 환경에 따라 **인사정보 및 SSO 연동을 제공**합니다. 기업 도입 환경에 따라 '사용자 관리' 메뉴에서 제공되는 기능과 표시 정보가 다를 수 있습니다. 자세한 내용은 IMQA 담당자에게 문의하세요.
</Gha>

![gm_user-attr.png](img/gm_user-01-nh.png)

IMQA 사용자 관리는 다음과 같이 구성됩니다.

**❶ 툴바(사용자 관리)**

**❷ 사용자 목록**

---

### 툴 바

**❶ 사용자 목록 동기화:** 기업 인사정보를 IMQA로 연동한 경우, 사용자 목록 동기화 내역을 확인하거나 수동으로 동기화할 수 있습니다.

**❷ 새로운 사용자:** 새 사용자를 등록합니다.

### 사용자 목록 동기화

<Gha keyword="NOTE" title="사용자 목록 동기화">
기업 인사정보를 IMQA로 연동한 경우 제공되는 기능입니다.
</Gha>

기업 인사정보와 IMQA 사용자 목록이 연동 되어 있는 경우, 예약된 일정에 따라 자동 업데이트됩니다. 정상적으로 사용자 목록이 업데이트되지 않은 경우 또는 즉시 업데이트가 필요한 경우에 현재 인사정보를 바로 반영하도록 사용자 목록을 수동으로 동기화할 수 있습니다. 

![gm_user-s-manualsync-nh.png](img/gm_user-s-04-nh.png)

❶ 사용자 목록 동기화 내역을 최근 5건까지 확인할 수 있습니다.

❷ 정상적으로 사용자 목록이 업데이트되지 않은 경우 또는 즉시 업데이트가 필요한 경우 [동기화] 버튼을 클릭합니다.

<Gha keyword="WARNING" title="사용자 목록 수동 동기화 시 주의 사항">
사용자 목록 동기화 완료에 다소 시간이 소요될 수 있으며, 페이지를 이동하는 경우에도 동기화는 취소되지 않고 진행됩니다. 사용자 목록 동기화 결과를 확인하시려면 페이지를 이동하거나 이탈하지 말고 잠시만 기다려 주세요.
</Gha>


### 사용자 추가

<Gha keyword="TIP" title="이메일 주소 또는 인사정보로 사용자 추가">
IMQA는 기본 로그인 ID로 '이메일 주소'를 사용하고, 새로운 IMQA 사용자를 추가하고 관리할 수 있는 **사용자 관리** 기능을 제공합니다. 또한 기업 도입 환경에 따라 **인사정보 및 SSO 연동**이 되어있는 경우, '사번'과 같은 기업 연계 정보로 사용자를 수동 추가할 수 있습니다.
</Gha>

#### | 이메일 주소로 사용자 추가

사용자 관리 페이지 오른쪽 상단의 [+ 새로운 사용자] 버튼을 클릭하면 이메일 주소로 사용자를 추가할 수 있는 팝업이 표시됩니다.

![gm_user-s-02.png](img/gm_user-s-02.png)

<Gha keyword="TIP" title="사용자 권한">
IMQA에는 앱 접근 권한과 기능 접근 권한으로 구분된 권한 체계가 있습니다. 사용자는 소속 팀과 역할을 기반으로 각 권한을 상속받습니다. 팀은 앱 접근 권한을 사용자에게 부여합니다. 역할은 기능 접근 권한을 사용자에게 부여합니다.
</Gha>

<Gha keyword="NOTE" title="(기본 팀)">
`(기본 팀)`은 모든 앱의 접근 권한을 가질 수 있습니다.
</Gha>

❶ 사용자의 소속 **팀**을 설정합니다. 기본은 `(기본 팀)`으로 설정되어 있습니다.

❷ 이메일 주소와 이름을 입력합니다. 이메일 주소는 로그인 ID로 사용됩니다.

❸ 사용자의 역할을 설정합니다. 역할에 따라 할당된 기능별 권한이 자동 설정됩니다.
- **SUPER_USER**: 전체 리소스와 관리 메뉴 접근 및 기능 사용이 가능한 통합 관리자 역할입니다.
- **ADMIN**: 대부분의 리소스와 관리 메뉴에 접근 및 중요 기능 사용이 가능한 관리자 역할입니다.
- **MANAGER**: 서비스별 관리 메뉴에 접근 및 일부 기능 사용이 가능한 담당자 역할입니다.
- **USER**: 권한이 있는 서비스에 접근 가능하나, 관리 메뉴 접근 및 기능 사용은 불가능한 일반 사용자 역할입니다.

❹ 정보 작성이 완료되면 [추가] 버튼을 클릭합니다.


#### | 인사정보로 사용자 추가

<Gha keyword="NOTE" title="사용자 목록 동기화">
기업 인사정보를 IMQA로 연동한 경우 제공되는 기능입니다.
</Gha>

기업 인사정보와 IMQA 사용자 목록이 연동 되어 있는 경우, 예약된 일정에 따라 자동 업데이트됩니다. 정상적으로 사용자 목록이 업데이트되지 않은 경우 또는 즉시 IMQA 사용자 추가가 필요한 경우에 인사정보로 사용자를 추가할 수 있습니다. 

사용자 관리 페이지 오른쪽 상단의 [+ 새로운 사용자] 버튼을 클릭하면 인사정보로 사용자를 추가할 수 있는 팝업이 표시됩니다. 

![gm_user-s-manualadd-nh.png](img/gm_user-s-05-nh.png)

<Gha keyword="TIP" title="사용자 권한">
IMQA에는 앱 접근 권한과 기능 접근 권한으로 구분된 권한 체계가 있습니다. 사용자는 소속 팀과 역할을 기반으로 각 권한을 상속받습니다. 팀은 앱 접근 권한을 사용자에게 부여합니다. 역할은 기능 접근 권한을 사용자에게 부여합니다.
</Gha>

<Gha keyword="NOTE" title="(기본 팀)">
`(기본 팀)`은 모든 앱의 접근 권한을 가질 수 있습니다.
</Gha>

❶ 사용자의 소속 **팀**을 설정합니다. 기본은 `(기본 팀)`으로 설정되어 있습니다.

❷ **로그인 ID**(예: 사번)와 이름을 입력합니다. 

❸ 사용자의 역할을 설정합니다. 역할에 따라 할당된 기능별 권한이 자동 설정됩니다.
- **SUPER_USER**: 전체 리소스와 관리 메뉴 접근 및 기능 사용이 가능한 통합 관리자 역할입니다.
- **ADMIN**: 대부분의 리소스와 관리 메뉴에 접근 및 중요 기능 사용이 가능한 관리자 역할입니다.
- **MANAGER**: 서비스별 관리 메뉴에 접근 및 일부 기능 사용이 가능한 담당자 역할입니다.
- **USER**: 권한이 있는 서비스에 접근 가능하나, 관리 메뉴 접근 및 기능 사용은 불가능한 일반 사용자 역할입니다.

❹ **사용자 속성 정보**를 키-값 형태로 입력할 수 있습니다. 

<Gha keyword="TIP" title="사용자 속성 정보">
 사용자 속성 정보의 **키가 사용자 목록에 컬럼으로 표시**됩니다. 이미 추가되어 있는 사용자 속성 키 정보와 동일하게 사용하고자 하는 경우, **오탈자에 주의**해 주세요. 기업 인사정보와 IMQA 사용자가 연동 되어 있는 경우, 기존 연동되어 있는 사용자 정보와 동일한 정보를 **키**로 입력해 주세요. 
</Gha>

❺ 정보 작성이 완료되면 [추가] 버튼을 클릭합니다.


### 📌 사용자 권한

사용자별 권한은 사용자의 소속 팀과 역할에 설정된 권한으로 기본 설정됩니다.
<Gha keyword="NOTE" title="팀-역할-사용자 권한 요약">
<h5>**1. 팀 단위로 앱 접근 권한을 설정할 수 있습니다.**</h5>
<p> - 팀 단위에는 기능 접근에 대한 설정 기능을 제공하지 않습니다.</p>
<h5>**2. 역할 단위에는 기능 접근 권한이 사전 정의되어 있습니다.**</h5>
<p> - 역할 단위에는 앱 접근에 대한 설정 기능을 제공하지 않습니다.</p>
<p> - 현재 역할을 새로 생성하거나 역할별 권한은 수정이 되지 않습니다.</p>
<h5>**3. 사용자 단위로 팀과 역할을 설정할 수 있습니다.**</h5>
<p> - 사용자는 기본 `(기본 팀)`으로 소속되며, `(기본 팀)`은 모든 앱의 접근 권한을 가지고 있습니다.</p>
<p> - 사용자의 소속 팀을 설정하면 팀에 설정된 앱 접근 권한을 자동 설정합니다.</p>
<p> - 사용자가 복수의 팀에 설정된 경우 각 팀에 설정된 앱 접근 권한을 병합합니다.</p>
<p> - 사용자의 역할을 설정하면 역할에 설정된 기능 접근 권한을 자동 설정합니다.</p>
<h5>**4. 사용자 단위로 소속 팀과 역할에 지정된 권한을 상속받아야 합니다.**</h5>
<p> - 현재 사용자에게 별도 앱 접근 권한과 기능 접근 권한을 설정할 수 없습니다.</p>
</Gha>

#### 팀에 따른 앱 접근 권한

IMQA는 여러 사용자를 팀으로 관리할 수 있습니다. 팀 단위로 앱 접근 권한을 설정하여 같은 소속 사용자들의 권한을 일괄 관리하기 용이합니다.

#### 역할별 기능 권한

IMQA는 역할에 따라 메뉴 및 기능 접근 권한을 구분하여 제공하고 있습니다. 아래의 역할별 기능 권한을 참고하세요.

<Gha keyword="WARNING" title="메뉴 접근 권한 제어">
<p>사용자의 역할에 기능 접근 권한이 있더라도, 소속 팀의 앱 접근 권한 유무에 따라 접근할 수 없는 메뉴가 있습니다. * 표시 메뉴는, 사용자가 특정 서비스(앱)에 대한 접근 권한이 있어야 접근이 가능합니다.</p>
<ul>

</Gha>

<Gha keyword="WARNING" title="데이터 드롭 정책 사용시 주의 사항">
데이터 드롭 정책 사용은 현재 수집 서버가 모든 데이터를 정상적으로 수신할 수 없는 상태인 경우에 활용될 수 있습니다. 일반적으로 운영 환경에서 사용자의 네트워크 상태에 따라 데이터 전송이 실패하는 경우가 다수 발생할 수 있습니다 (예: 엘리베이터 탑승 중). 데이터 드롭 정책은 해당 세션(실행) 동안의 재시도 횟수 초과 시 전송에 실패한 데이터를 삭제하므로 1개 세션에서 일부 데이터가 유실되는 데이터 정합성 이슈가 발생할 수 있습니다. 정책 사용시, 최대 재시도 횟수를 점진적으로 조정하며 관리하는 것을 권고합니다. 자세한 내용은 IMQA 담당자에게 문의해 주세요.
</Gha>

## 5. 매핑 파일 관리

IMQA 매핑 파일 관리를 통해 앱 버전별 매핑 파일을 업로드하여 ProGuard, Symbolication 등이 적용된 앱에서 클래스 명과 함수 명을 가독화할 수 있습니다. 

<Gha keyword="NOTE" title="지원되는 난독화 종류 및 업로드 파일 크기 제한">
<p>IMQA는 현재 앱 유형별 아래의 역난독화를 지원하고 있습니다. 난독화 종류는 지속적으로 업데이트 예정입니다.</p>
<ul>
  <li>- **Android**: ProGuard, Allatori, Source Map(웹뷰)</li>
  <li>- **iOS**: dSYM, Source Map(웹뷰)</li>
  <li>- **Web**: Source Map</li>
</ul>
<p>매핑 파일 업로드 시, 200MB 이하의 매핑 파일만 업로드할 수 있습니다. 제한 용량 이상의 파일 업로드는 IMQA 담당자에게 문의해 주세요.</p>
</Gha>
<Gha keyword="TIP" title="매핑 파일의 적용 시점">
ProGuard, dSYM 등의 경우, 매핑 파일 업로드 이후부터 수집되는 난독화 정보를 가독화 하여 저장합니다. 업로드 한 매핑 파일 적용에 다소 시간이 소요될 수 있으며, 스택 트레이스 조회 시점에 난독화 정보로 보여질 수 있습니다. 
Source Map의 경우, 수집된 웹 에러 스택 트레이스 정보 조회 시 먼저 웹 버전이 일치하는 소스맵 파일을 즉시 적용합니다. 일치하는 웹 버전 소스맵 파일이 없을 경우 앱 버전이 일치하는 소스맵 파일을 즉시 적용합니다.
</Gha>
