## 개요

- 기존 레거시 IMQA 제품 제거

- K3s 기반 컨테이너 오케스트레이션 환경 구축

## 볼륨 구성

K3s 설치 및 클러스터 구성 시 root 영역(VG_OS)에 설치/운영이 필요하며, Kubernetes 내부에서 실행되는 앱들이 직접적으로 사용하는 볼륨은 VG_APP 그룹을 사용합니다.

<Gha keyword="NOTE" title="VG_APP 볼륨 타입">
VG_APP의 타입은 반드시 **LVM**이어야 합니다.
</Gha>

<Gha keyword="NOTE" title="용량 산정 기준">
안정적인 운영에 초점을 두어 여유있게 산정하였으나, 실 운영 단계의 상황에 따라 다소 조정이 필요할 수 있습니다.
</Gha>

### K3s 서비스 및 권한 구성

<Gha keyword="NOTE" title="K3s 서비스 구동 방식">
- `k3s.service`는 **root 권한**(system service)으로 구동됩니다.
- `/run/k3s/containerd/containerd.sock` 접근을 위해 `containerd` 사용자 그룹을 생성하고, 운영 사용자 계정을 해당 그룹에 추가해야 합니다.
</Gha>

### containerd 그룹 및 소켓 권한 설정

운영 사용자가 `kubectl`, `crictl`, `ctr` 명령을 사용하려면 containerd 소켓에 접근 권한이 필요합니다.

```bash
# containerd 그룹 생성 (설치 시 root 권한 필요)
sudo groupadd -f containerd

# 운영 사용자를 containerd 그룹에 추가 (설치 시 root 권한 필요)
sudo usermod -aG containerd <username>

# containerd 소켓 그룹 권한 설정 (설치 시 root 권한 필요)
sudo chgrp containerd /run/k3s/containerd/containerd.sock
sudo chmod g+rw /run/k3s/containerd/containerd.sock
```

### 사용자 소유권 설정이 필요한 디렉토리

| 경로 | chown 명령 | 용도 |
|------|------------|------|
| `/etc/rancher/` | `chown -R <user>:<user> /etc/rancher/` | K3s 설정 파일 접근 |
| `/var/lib/rancher/` | `chown -R <user>:<user> /var/lib/rancher/` | K3s 데이터 관리 |

## IMQA 설치 절차

### 1단계: IMQA SDK 검증단계

- Android/iOS SDK 개발계 테스트
  - 빌드 이슈 확인 및 기술 지원
  - 난독화 모듈 확인
- Web Agent(Browser SDK) 개발계 테스트
  - 빌드 이슈 확인 및 기술 지원
  - 소스맵 연동 여부 확인

### 2단계: IMQA 설치 사전 준비

- Root 권한 요청 (설치 시에만 필요)
- IMQA 오프라인 설치 패키지 전달 및 수령
